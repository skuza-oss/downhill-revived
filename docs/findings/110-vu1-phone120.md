## The two changes

1. **Lean clipping frame** (`port/runtime/vu0_interp.c`,
   `port/tools/vu1_native_clip.py`). The closed native clipping kernel now reads
   VU1 data memory through a fixed physical pointer (`lower_cached`'s
   `ps2_q128 *__restrict data`) instead of the generic VU0/VU1 accessor, so the
   compiler can keep the pipeline fields it uses in a private frame instead of
   reloading them across VU1 data stores. Nothing else changes: LQ/SQ/ILW/ISW/
   ILWR/ISWR and the VU0 register-file path are the same instructions, the same
   stalls and the same order. Every native caller's `NATIVE_SAVE` already zeroes
   `n_flags`/`q_ready` and adds 64 cycles before the call, so component-ready
   timestamps have expired and the flag/Q state is empty at entry; the copy-back
   restores MAC/status/clip/Q/lazy/VI state. P reads and writes are asserted
   absent. Callers that pass NULL keep the old accessor bit for bit.
2. **AOT readiness-check skip** (`port/tools/vu1_aot.py`). A straight-line AOT
   block now tracks its own component readiness in `ReadyOperands`: `None` is an
   unknown entry timestamp and keeps the runtime check, a write becomes ready four
   cycles later, a checked read is ready at once, and every emitted pair consumes
   at least one cycle. The emitted `if` therefore never omits a check the runtime
   arrays would have reported as not-ready, and the runtime ready arrays stay
   intact for every other block. The only state the skip can understate is the
   block's local cycle counter `u->cycle`; no game-visible path reads it directly
   (flag retirement and the VU0 1-cycle VI bypass use the same computed values the
   checked path computes, and the replay below compares the full CPU and data
   memory).
