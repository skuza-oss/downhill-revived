# 120: The FPS & Ping counter

`perf_counter` / `DHD_PERF_COUNTER` defaults to OFF. PC SETTINGS has a live
`FPS & Ping:` OFF/ON row beside V-Sync; the launcher exposes it too. The shared
settings crate supplies defaults, INI/environment handling and choices for every
host. `settings_table.h` is generated by `dhd_settings::table::c_table`; its
`tests/generated.rs` checks it (DHD_SETTINGS_BLESS=1 regenerates it).

`port/render/src/present/counter.rs` draws white public-domain bitmap glyphs over
a translucent black panel at the upper right, after the final picture, through
`Surface::draw_counter` in `dhdr_surface_present`. Integer pixel scaling gives
roughly 2% of the drawable height for the glyphs, independent of game resolution.
The original game display textures, GS capture and diagnostic referees are unchanged.
The counter measures successfully acquired pictures passed to surface presentation,
including interpolation, with a monotonic host clock and half-second samples.
This counts presentation submissions; a compositor may discard a submitted picture.

The native glue (`gpu_rust.c`, `gpu_rust_native.inc`) passes the switch and the ping
(`net_ping_ms`: a room or race with a known ping, else -1; a few fields, not a copy of the
lobby for every picture). The switch is read at the first picture and again when PC SETTINGS
changes it (`gs_present_options_apply`, on the game thread that sets it; the browser on
`web_env_changed`), not for every picture: getenv scans the environment (finding 090 SP14).
The bitmap is uploaded only when its numbers change (twice a second at most). The same
presenter covers native and exact rendering, movies, menus, races and loading
screens on Windows, macOS, Linux and Android. Browser glue (`gpu_rust_web.c`,
`gpu_rust_web_native.inc`, settings.js) supplies its monotonic WASI clock and live
setting. Browser online host services are currently stubs in worker.js, so there
is no browser room ping to show.

Font: digits, space and F/P/S/I/N/G/M copied from Daniel Hepper's
[font8x8_basic.h](https://github.com/dhepper/font8x8/blob/master/font8x8_basic.h).
Both the header and [README](https://github.com/dhepper/font8x8/blob/master/README)
explicitly say Public Domain; derived from Marcel Sondaar / IBM public-domain VGA
fonts. Checked upstream before adapting; embedding and modification are permitted.

Capture: DHD_SCREENSHOT reads the pre-present GS picture. For final-picture PNGs,
`DHD_CAPTURE_PRESENTED=<prefix>` enables a presenter readback after the counter;
DHD_CAPTURE_AT (default 10 seconds from first presented frame) and
DHD_CAPTURE_INTERVAL control it. Output is `<prefix>-000.png`, etc. Only a
surface offering COPY_SRC can be captured. The opt-in readback blocks for that
capture; normal play performs none.

Build: rustgs accepts a worktree on C: when its build/ folder resolves to another drive (a
junction); Cargo's own target and cache drive checks are unchanged.

Validation:
- Full wasm core: all 3,815 game units and 35 module units compiled; zero failed
  units; strict link OK; offset scan clean. The recompiler reported five unsupported
  functions, handled by the existing core; this is not a new matching-decomp claim.
- Windows x64 host: PASS, 133 generated imports, 37 host objects. Used the supplied
  SDL static library plus `--sdl-include` pointing at its
  `src/SDL3-3.4.18/include` directory. Build log checked for failed units and strict
  link failure, not just the process exit status.
- rustgs native and wasm32 checks passed. The settings crate's generated-header
  test passed (1 test); launcher and browser settings JS syntax checks passed.
- Browser graphics reactor built with `--threads --no-vu-aot`, including the new
  renderer import. The full AOT graphics build was stopped during compilation of
  the unchanged large VU interpreter; no full browser runtime session was run.
- Minimized Windows DX12 native runs: front-end menu and Mt. Midoule Freeride race
  inspected through the presenter's PNGs, with crisp white text and backing at the
  upper right. Menu capture reads 54 FPS; race reads 60 FPS. Offline ping is absent.
  The captures and logs stayed local (not in the repository).
  The tool capture mode measures the drawable even while minimized; without
  DHD_CAPTURE_PRESENTED, minimized windows still skip presentation as before.
- macOS, Linux and Android were not built or run on this Windows machine. Their
  drawing/ping paths share the tested native code. Online ping and changing the
  setting from the PC SETTINGS page were checked in source but not exercised in
  a runtime room/UI session. No benchmarks or long test suites were run.
